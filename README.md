# 技友SkillMate
> 以你所长，换我所爱。

**技友 SkillMate** 是一款面向年轻人的 C 端技能互换社交 App，致力于让每个人都能通过分享自身擅长的技能，获得学习其他技能的机会。
平台以「技能互换 + 兴趣社交」为核心，通过技能分享、双向需求匹配、交换邀约和学习交流，帮助用户发现志同道合的技能伙伴，建立互助学习关系，让知识与技能在人与人之间自由流动。

**https://bingqian0901.github.io/MTDemo/** 

## 一、项目背景
### 1.1 需求洞察
在日常生活中，越来越多的年轻人希望利用碎片化时间学习摄影、编程、吉他、英语等新技能，但传统学习方式仍存在一定门槛：
 **学习成本较高： 付费课程价格较高，部分兴趣类技能的学习需求难以通过低成本方式满足。
 **自学缺乏指导： 用户难以找到合适的学习伙伴，学习过程中缺少及时反馈和持续动力。
 **技能价值未被充分利用：很多人掌握一定的专业技能或兴趣特长，却缺少便捷的分享、交流和互换渠道。
 **供需匹配效率较低：现有兴趣社区侧重内容分享，用户难以快速找到既能教自己、又愿意学习自己所长的互补伙伴。
### 1.2 产品机会
每个人既可能是某项技能的学习者，也可能是另一项技能的分享者。
例如，擅长 Python 的用户希望学习摄影，而擅长摄影的用户恰好希望学习 Python。双方可以通过互相教学交换学习机会，不必完全依赖传统付费课程。
基于这一需求，技友 SkillMate 将用户的技能供给与学习需求进行双向匹配，通过轻量化的社交互动与交换流程，帮助用户建立真实的互助学习关系。

让每个人都能成为技能的分享者与学习者。
通过连接不同用户的技能与学习需求，让有价值的知识、经验和兴趣在用户之间流动，打造一个平等、友好、互助的技能学习社区。

## 三、目标用户与典型场景
### 3.1 目标用户
 **大学生群体**希望利用课余时间学习新技能、拓展兴趣爱好，同时愿意分享自己的专业知识和个人特长。
 **年轻职场人**希望利用碎片化时间提升职业技能、学习兴趣爱好，并通过技能交流建立新的社交关系。
 **兴趣技能爱好者**拥有摄影、绘画、音乐、运动等兴趣特长，希望找到志同道合的伙伴，分享经验并学习其他技能。
### 3.2 典型用户场景
小林是一名大学生，擅长 Python 和 Excel，但希望学习摄影。
小陈是一名摄影爱好者，擅长人像摄影与构图，希望学习 Python 编程。
小林在技友 SkillMate 发布自己的技能档案：
- 我能教：Python、Excel
- 我想学：摄影、吉他
系统通过双方技能供给与学习需求进行匹配，发现小林与小陈存在双向互补关系，并推荐以下交换方案：
**小林教小陈 Python，小陈教小林摄影。**
双方可以查看彼此的技能介绍，发起交换邀约，约定学习时间与形式，通过私信交流开展互助学习，并在完成后记录学习收获。

## 四、产品功能架构
技友 SkillMate 采用移动端 App 设计，以「内容发现—技能匹配—交换邀约—学习交流—成长记录」为核心用户路径。
底部导航包含五个一级功能模块：
**首页｜发现｜发布｜消息｜我的**
### 4.1 首页：兴趣内容与技能发现
首页是用户了解技能内容、发现兴趣和探索学习机会的主要入口。
核心功能：
- 个性化技能内容推荐
- 热门技能分类浏览
- 双列瀑布流技能笔记
- 技能内容详情查看
- 点赞、收藏与评论
- 今日技能搭子推荐
首页以兴趣内容为切入点，通过摄影、编程、音乐、设计等技能分享，帮助用户发现感兴趣的内容，并引导用户从内容浏览进入技能伙伴的个人主页。
用户不仅可以阅读技能笔记，还可以通过「向 TA 学习」进入技能交流与交换流程。
### 4.2 发现：智能技能匹配
发现页是产品的核心功能模块。
用户可以根据自己的学习需求搜索技能、筛选技能伙伴，并查看与自身需求互补的推荐用户。
主要功能：
- 技能关键词搜索
- 技能分类筛选
- 线上 / 线下学习方式筛选
- 技能伙伴推荐
- 双向技能匹配
- 匹配理由与交换方案展示
- 技能伙伴个人主页
系统根据当前用户「我能教的技能」和「我想学的技能」，与其他用户的技能档案进行匹配。
对于满足双向互补条件的用户，优先展示交换推荐方案，帮助用户理解双方可以如何互相学习。
### 4.3 发布：技能分享与学习需求表达
发布功能用于帮助用户建立个人技能档案，向社区表达自己的技能供给和学习需求。提供三个主要发布入口：
 **发布我能教的**填写技能名称、技能分类、熟练程度、技能介绍、可教授内容及教学形式，让其他用户了解自己的技能特长。
 **发布我想学的**填写目标技能、当前学习基础、学习目标和期望学习方式，帮助系统发现具有相关技能的学习伙伴。
 **分享技能笔记**支持发布技能相关的图文内容，包括标题、封面、正文和技能标签。
发布后的内容将进入社区信息流，并展示在用户个人主页中。
用户可以同时拥有多项擅长技能与学习目标，并根据实际情况进行新增、编辑或删除。
### 4.4 消息：私信交流与交换邀约
消息模块承担用户沟通、邀约确认和交换协作的功能。主要功能：
- 技能伙伴私信聊天
- 历史消息查看
- 技能交换邀约卡片
- 收到与发出的交换通知
- 交换状态反馈
- 学习时间与方式沟通
用户可以在发起正式交换前，通过私信了解对方的技能水平、学习目标与交流安排。
发起交换后，系统在对应会话中展示交换邀约卡片，方便双方查看交换内容、确认安排并跟进交换进度。
### 4.5 我的：个人技能档案与学习成长
个人中心集中展示用户的技能能力、学习需求、发布内容及技能交换记录。主要功能：
- 个人资料编辑
- 我能教的技能
- 我想学的技能
- 技能笔记管理
- 我的交换
- 学习记录与成长数据
- 交换评价
「我的交换」按照待确认、进行中和已完成三个状态进行分类管理，帮助用户查看不同阶段的交换任务。
完成交换后，用户可以记录学习收获并进行评价，逐步沉淀自己的技能学习经历。

## 五、核心产品机制
### 5.1 双向技能匹配
双向技能匹配是技友 SkillMate 的核心设计。
传统技能学习平台主要关注「用户想学什么」，而 SkillMate 同时关注两个维度：
 **技能供给：** 用户能够教授什么技能？
 **学习需求：** 用户希望学习什么技能？
当双方的技能供给与学习需求相互满足时，即可建立双向技能匹配关系。
例如：
| 匹配维度 | 小林 | 小陈 |
| --- | --- | --- |
| 我能教的 | Python | 摄影 |
| 我想学的 | 摄影 | Python |
| 交换方案 | 教小陈 Python | 教小林摄影 |

系统识别双方的互补关系后，在推荐卡片中展示：
**双向契合：你教 TA Python，TA 教你摄影。**
对于只有单向学习需求匹配的用户，平台仍支持技能发现与私信沟通，但会明确区分单向匹配和双向互换，避免产生不准确的推荐结果。
匹配结果根据双方技能档案动态生成。当用户新增或修改技能后，系统同步更新匹配关系。

### 5.2 从内容发现到技能交换
技友 SkillMate 不仅是技能信息展示平台，更是围绕用户实际学习需求设计的兴趣社区。
用户可以通过技能笔记发现感兴趣的内容，再进入作者主页了解对方的技能信息。
如果双方存在互补需求，便可以进一步发起技能交换。
通过「内容吸引—兴趣建立—技能匹配—互动交换」的路径，将社区内容浏览与真实学习需求连接起来。
### 5.3 技能交换闭环
平台设计完整的技能交换流程：
1. **发布技能：** 用户填写能够教授的技能及希望学习的技能。
2. **发现伙伴：** 系统根据双方技能信息推荐具有互补需求的用户。
3. **发起邀约：** 用户选择交换技能、学习方式和期望时间，向对方发出邀约。
4. **确认交换：** 双方确认交换内容与学习安排，建立学习关系。
5. **学习交流：** 通过消息沟通、学习安排和进度管理开展技能互换。
6. **完成互评：** 交换结束后记录学习成果，填写评价并沉淀学习经历。
通过完整的状态流转，让技能互换从一次兴趣表达转化为可跟进、可完成的实际学习活动。
### 5.4 用户信任与交换安全
为提升用户参与技能互换的信任感，平台在产品设计中考虑以下机制：
- 用户可查看对方的技能介绍、学习需求及历史交换评价。
- 用户可在正式交换前通过私信沟通。
- 交换邀约需经双方确认后进入进行中状态。
- 用户可以撤回尚未确认的邀约。
- 交换评价与已完成的交换记录关联。
- 默认不公开用户联系方式与精确位置。
通过信息透明、双向确认和交换评价，降低陌生用户之间建立学习关系的沟通成本。

## 七、交互与视觉设计
### 7.1 设计理念
产品以年轻化、轻量化、社交化为主要设计方向，降低用户发布技能、寻找伙伴和发起交流的操作门槛。
整体设计关键词：
**年轻、清新、友好、互助、陪伴、成长。**
### 7.2 视觉风格
 **主色调：** 蓝紫色与薰衣草紫，营造轻松、友好的社区氛围。
 **背景设计：** 以白色和浅灰色为主，突出技能内容与人物信息。
 **页面布局：** 采用移动端卡片式设计，保持清晰的信息层级。
 **组件设计：** 使用圆角卡片、技能标签、头像、底部抽屉和轻量弹窗。
 **交互反馈：** 通过按钮状态、Toast、页面转场及操作反馈提升使用体验。
### 7.3 移动端优先
产品采用 C 端移动 App 的交互形式设计，以手机屏幕为主要展示载体。
在移动浏览器中，页面适配手机屏幕；在桌面浏览器中，以居中的手机尺寸预览区域展示 App 界面。
通过底部 Tab 导航、内容信息流、用户主页、聊天气泡和底部操作栏，模拟真实移动端社交产品的使用体验。

## 八、Demo 设计与实现
### 8.1 Demo 目标
本项目以高保真交互 Demo 的形式展示技友 SkillMate 的产品设计方案。
重点验证与展示三个核心问题：
1. 用户能否便捷地表达自己擅长的技能和想学习的技能？
2. 平台能否识别双方的互补需求，并提供清晰的技能交换建议？
3. 用户能否通过连续的交互操作，从发现伙伴走到完成一次技能交换？
### 8.2 技术实现方案
前端 Demo 采用以下技术方案：
| 技术 | 用途 |
| --- | --- |
| React | 页面组件与交互状态管理 |
| Vite | 前端项目构建与开发 |
| Tailwind CSS | 页面布局与移动端视觉样式 |
| Lucide Icons | 图标与交互元素 |
| localStorage | 本地演示数据与操作状态持久化 |
技能匹配采用基于双方技能供需关系的规则匹配机制，不依赖真实大模型接口。
演示版本通过本地模拟数据展示内容推荐、技能匹配、聊天交流和交换状态变化。
聊天消息、邀约确认及学习记录为前端模拟交互，不代表已实现真实多用户即时通信或线上教学服务。
### 8.3 预置演示场景
默认用户：小林
- 我能教：Python、Excel
- 我想学：摄影、吉他
预置技能伙伴：
- 小陈：擅长摄影，希望学习 Python。
- 小周：擅长吉他，希望学习 Excel。
- 小吴：擅长英语，希望学习 Python。
通过上述数据，可以展示双向技能匹配、单向需求匹配及不同交换方案。
用户可通过修改个人技能档案，体验匹配结果动态变化。
### 8.4 演示路径
建议按照以下顺序体验核心功能：
**首页浏览技能笔记 → 发现技能伙伴 → 查看双向匹配方案 → 发起交换邀约 → 消息交流 → 模拟确认邀约 → 完成技能交换 → 评价并查看学习记录。**

## 九、产品设计亮点
### 9.1 通过技能互补建立双向学习关系
区别于单向授课模式，将用户同时视为技能的提供者和学习者。
通过双方技能供给与需求的匹配，发现能够互相帮助的学习伙伴。
### 9.2 内容社区与技能交换相结合
通过技能笔记、兴趣内容与用户主页，让用户从感兴趣的内容出发，自然进入技能发现和交流场景。
内容不仅用于知识分享，也成为建立技能交换关系的入口。
### 9.3 从匹配推荐到学习完成的完整闭环
围绕技能互换的实际流程，设计邀约、确认、交流、进度管理与评价机制。
用户不只是在平台上找到一个技能伙伴，还能够持续跟进双方的学习交流与交换结果。
### 9.4 降低普通用户的参与门槛
采用熟悉的移动端社区交互形式，用户无需学习复杂的功能流程，即可完成技能发布、伙伴发现和交换邀约。
通过轻量化的技能档案、可解释的匹配理由和直观的交换方案，让技能互换变得更加简单。

## 十、产品后续规划
当前 Demo 重点展示核心业务流程与移动端交互体验。后续可围绕真实用户需求和实际使用反馈，逐步拓展以下能力：
- **真实用户体系：** 支持账号注册、身份认证、个人资料与技能档案管理。
- **多维技能匹配：** 结合技能水平、学习目标、空闲时间及教学方式优化推荐结果。
- **实时通信：** 支持真实用户私信、邀约通知和交换协作。
- **学习成长体系：** 通过学习目标、交换记录与成长展示，帮助用户持续积累学习成果。
- **社区信任机制：** 完善用户评价、内容举报、隐私保护及交换安全管理。
产品将持续围绕「帮助用户发现合适的技能伙伴，建立真实的互助学习关系」这一核心目标进行迭代。
